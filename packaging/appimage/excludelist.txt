# Graphics WSI + Vulkan loader — MUST be host-provided to match the running
# compositor and GPU driver. Bundling the Debian-bookworm build copies shadows
# the host's (newer) libs and breaks surface creation on Wayland: the bundled
# libvulkan loader fails to expose VK_KHR_wayland_surface for the host RADV/AMD
# driver, and the bundled libwayland-egl/libwayland-client mismatch the
# compositor. Symptoms: alpha.10 GL panic (wgpu-hal egl.rs unwrap), alpha.11
# "Failed to create surface for any enabled backend". Host provides all of
# these on any Wayland/X11 desktop; removing the bundled copies fixes launch.
libvulkan.so*
libwayland-client.so*
libwayland-cursor.so*
libwayland-egl.so*
libxkbcommon.so*
# Mesa / OpenGL / GBM / LLVM — GPU-driver-coupled, MUST be host-provided.
# Same failure class as the Vulkan/Wayland libs above (and the reason a
# Wayland/GL desktop still hit "Failed to create surface" even after those
# were excluded): the Debian-bookworm Mesa stack (libGL/libEGL/libgbm and the
# libLLVM it links for llvmpipe/radeonsi) shadows the host's *newer* Mesa and
# breaks GL/EGL surface creation + software/GPU rasteriser init on an ABI
# mismatch. libdrm is likewise kernel/Mesa coupled (it is no longer
# force-bundled — see build-appimage.sh). The host always provides all of
# these on a real X11/Wayland desktop.

libLLVM-*.so*
libGL.so*

libGLX_mesa.so*
libEGL.so*
libEGL_mesa.so*
libGLdispatch.so*
